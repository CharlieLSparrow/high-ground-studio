# Studio transcript review checkpoint — 2026-08-04

## Outcome

Imported episode media now uses the same canonical correction and verification substrate as Capture sessions. The Episode Editor has a paged, source-bound review desk that exposes provider word timing and probability, operates the exact protected source player, and records either a versioned correction overlay or a confirmed-as-heard receipt.

Provider segments, provider words, source media, timelines, tasks, goals, and published artifacts remain unchanged by transcript review.

## Shared review model

- `TranscriptCorrection` now relates directly to `TranscriptJob`; its room is optional so Studio media does not require a synthetic `CallRoom`.
- `TranscriptSegmentVerification` supports exactly one playback source family: a Capture `RecordingAsset` with a room, or a Studio `StudioMediaAsset` without one. A database check constraint enforces this boundary.
- Existing Capture room deletion cascades are preserved. A second migration explicitly restores those lifecycle semantics after the source generalization.
- Studio corrections bind to the transcript job, provider text hash, segment clock, current accepted overlay, media hash/generation, source id, reviewer, and playback position.
- A reviewed correction supersedes the prior active overlay under a serializable transaction and advisory segment lock. Historical rows and revision receipts remain.
- Confirming provider text as heard creates a separate append-only verification. It does not manufacture a no-op correction.

## Review UX

- Transcript pages load 40 segments at a time; the API caps pages at 80.
- Each segment exposes its effective reviewed text while preserving the original provider text/hash.
- Provider words remain individually timed. Probability is color-coded and labeled as provider probability, never measured accuracy.
- Selecting a segment seeks and plays its exact source range.
- Correction and as-is controls remain disabled until the protected player reaches the selected segment.
- Text and speaker edits are one reviewed overlay. With the current local provider, speaker identity remains per-segment human review because diarization is explicitly unavailable.
- The desk distinguishes active overlays from retained correction receipts and from as-is playback verifications.

## Retained operation

Signed-out access returned 401 and an unrelated retained account returned 403. A correction/verification attempt without playback confirmation returned 409 `PLAYBACK_NOT_CONFIRMED`; database counts were unchanged and the source hash remained unchanged.

No valid correction or as-is receipt was generated by automation. Those receipts make a human-listening claim and remain intentionally open until a person operates the source player and reviews the audio.
