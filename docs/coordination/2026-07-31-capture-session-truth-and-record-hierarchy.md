## Defects found by doing the work

The retained run series intentionally kept its Sessions so the failures remain
auditable.

- **AN** found that an endpoint-specific `/api/nest-chat` 401 signed out an
  otherwise valid native account. A forced refresh had already proved the same
  token through canonical `/api/mac/session-check`; the second feature denial
  therefore belonged to chat, not global identity.
- The native auth boundary now returns that feature response to its caller and
  does not evict a canonically verified account. Callers remain responsible for
  interpreting every returned HTTP status.
- Nest chat now authenticates through the shared Firebase-bearer-or-browser-
  cookie session boundary. Native Capture and the browser no longer use
  conflicting identity paths for the same episode thread.
- A legitimate missing canonical episode thread now stops five-second
  background polling after its terminal 404. Manual refresh remains available,
  and an owner-bound protected cache remains readable without pretending it is
  current or editable.
- **AO** proved the account stayed signed in and the exact Session restored,
  then exposed unreliable interaction with the standard disclosure control.
- **AP** proved the new control expanded, then exposed a test defect: large
  swipes could skip the provider boundary. The test now advances incrementally
  until the visible boundary is actually hittable.
- **AQ** passed the complete retained create, terminate, relaunch, exact-Session
  restore, authority-settle, consent, recorder, readiness, and boundary
  readback journey.
