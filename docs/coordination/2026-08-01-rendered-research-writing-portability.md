# Rendered Research-to-writing portability — 2026-08-01

## Outcome

The retained local Nest now has a repeatable, credential-safe product operation for:

`exact source passage -> private tagged annotation -> private writing response -> browser download -> verified restore -> same-bundle retry -> separate-account denial`

The final operation passed through rendered Quipsly at `http://127.0.0.1:3012`; PostgreSQL was used only for independent boundary readback. No provider, production service, external URL, message, calendar, delivery, publication, or billing system was mutated.

## Product defects found and fixed

1. Annotation purpose, annotation visibility, and restore destination were visually labelled but did not expose stable unique accessible names. Explicit accessible names now make those controls reliable for people using assistive technology and for retained browser operation.
2. The editor proof could accept its initial **Saved** badge before a newly entered response crossed the persistence boundary. The retained operator now requires an observable unsaved/saving state before accepting the final **Saved** state.
3. Research export carried the pinned evidence block but omitted the human-authored response block whose identity was already retained in `StudioSourceAnnotationUse.sourceJson`. That made the portable-writing claim incomplete.

The additive schema-v1 export now includes an optional linked `responseBlock` snapshot beside the canonical evidence block. Validation binds it to the exact `sourceJson.responseBlockId`. Restore creates both blocks privately, rebinds the restored response-block ID and stable ID, retains the canonical writing use on the evidence block, versions changed snapshots, and reuses every identity on an exact retry. Older v1 bundles without response snapshots remain readable.
