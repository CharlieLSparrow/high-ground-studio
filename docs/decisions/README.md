# Architecture decisions

Use an architecture decision record (ADR) for a durable choice that affects
multiple surfaces, data contracts, security boundaries, deployment, or a
significant migration.

## Status values

- `proposed`: under active review;
- `accepted`: current direction;
- `superseded`: replaced by a later ADR;
- `deprecated`: retained only for compatibility.

## Records

- [ADR 0001: Retain a product monorepo during convergence](0001-product-monorepo-during-convergence.md)

## Creating a record

1. Copy [the template](0000-template.md).
2. Choose the next four-digit number.
3. Describe context, decision, alternatives, consequences, migration, and proof.
4. Link affected runbooks and earlier decisions.
5. Change status only through review.

ADRs capture decisions, not task lists or session logs.
